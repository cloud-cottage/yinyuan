## 2. 边缘缓存真缺陷与修法（§7.15-2）

- **缺陷形态**：`200` 响应曾附 `Vercel-CDN-Cache-Control` ⇒ 边缘缓存命中的请求不进入函数 ⇒ **(a) 不计数（配额可绕过）**；**(b) `X-RateLimit-Remaining` 停在旧值（对外读数错数）**。
- **实测读数**：固定 URL 连打 3 发 ⇒ `x-vercel-cache: HIT` ＋ `Remaining` 恒 **987**；同端点改打 unique URL（随机查询串强制回源）⇒ **986 → 985 → 984** 逐发递减。
- **修法口径（落地归实现单）**：API 响应一律不允许边缘缓存 —— 移除 `Vercel-CDN-Cache-Control` 与因此不再需要的 `Vary: Authorization, X-API-Key`；**保留实例级缓存**（第 1 级一字未改）。
- **实现侧落地线索（只读登记、未复核线上效果）**：本单收尾时本仓已有提交 `2db521f`（`fix(api): 移除 API 响应的边缘缓存指令（固定 URL 命中 CDN 时不计数 + Remaining 陈旧）`；改动面 `api/_lib/respond.js` ／ `api/_lib/cors.js` ／ `api/_lib/ratelimit.js`），口径与本节修法一致。**本单未复核代码全文、未线上复测、未跑质检 ⇒ 不得写成「修法已上线 ／ 已验收」**。
- **取舍登记**：以边缘缓存换「限流计数正确性 ＋ 对外读数正确性」，属正确性优先；**不得以延迟回退为由恢复边缘缓存**（需另走 §0.4 升版）。
