| 端点 | 字段 |
| --- | --- |
| `dynasties` | `data.total`（＝15）、`data.items[{seq,value}]`、`data.counts.faces` ／ `.seals`、`data.unrecorded.faces` ／ `.seals` |

| `inscriptions` | `data.total` ／ `limit` ／ `offset` ／ `items[7]`：`id`、`collection`（`seals` / `faces`）、`seal_name`、`transcription`、`author`、`dynasty`、`seal_type` |

**判负（双向）**：(a) 文档列了响应里没有的字段（`_id`、`created_at`、`name_full`、`native_place_chs`、`cbdb_id`、`review_status`、`seal_code`、`source_book`、`source_page_no` 等）；(b) 漏列必有字段；(c) 字段名改写 / 大小写改写 / 自造别名；(d) `items` 写成裸数组、不写信封；(e) 示例 `items` 用「…」省略已列字段。

### 3.3 示例与 `total`（动态值）

- 信封：成功 `200 {ok:true,data:{…}}`；失败 `{ok:false,reason,message}`（无 `data`）。
- **`authors` / `inscriptions` 的 `total` 为动态值**（核验时点 `570` / `158`）：示例须标「**示例值，实际以响应为准**」或以占位符表达（如 `"total": <当前条数>`）；**不得写成固定值 / 承诺值 / SLA / 数据量宣传；不得隐去 `total`**。
- `limit` **上限 200 必须入文**；`dynasties` 的 `items` 示例可只列前 2 项但须明写「共 15 项」，`counts` 与 `unrecorded` 结构须完整。

### 3.4 必留字样与安全提示

- **「每日最多 1000 次」逐字保留**，并写明「**按 API key 计数**」（不得写按 IP ／ 按端点 ／ 按域名 ／ 不限次数）。
- **「浏览器直连与密钥安全」提示必须存在**（新章节对接说明处或页面既有对接说明区，二者其一）：(a) 浏览器内用 key 会暴露给终端用户（DevTools ／ 网络面板 ／ 前端产物）；(b) 官方建议客户走后端代理（key 只存服务端）；(c) 浏览器直连只适合试用 ／ 演示 ／ 内部工具。**禁写「前端直连安全」「可把 key 写进前端」**。

### 3.5 对客文案纪律（可判负）

- **禁实现者口吻**：占位 ／ 占位数据 ／ 里程碑 ／ 路由 ／ 入口 ／ 批次 ／ 待补 ／ 接口改造 ／ 联调 ／ 回归 ／ 灰度（指代接口能力时）。
- **禁实现细节**：进程内 ／ 实例 ／ 句柄 ／ 连接池 ／ 集合 ／ 字段映射 ／ 适配层 ／ 环境变量（及变量名）；**存储选型名（`Redis` ／ `KV` ／ `Upstash` ／「计数器存储」）**。
- **允许**：接口名 ／ 全路径 ／ 方法 ／ 请求头名 ／ 查询参数名 ／ 响应字段名 ／ 错误码与 `reason` 值。
- **取样**：`/docs` 页渲染后的可见文本（含表格单元、代码块、说明段、折叠区）。
