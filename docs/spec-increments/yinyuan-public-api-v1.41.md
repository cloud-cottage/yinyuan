## 四、缓存与延迟口径（可判负；规范落位 §7.12-4 / AC-124、AC-125、AC-127）

| 层 | 口径 | 判负形态 |
| --- | --- | --- |
| 实例内（第 1 级） | **TTL 60s**；键 ＝ `<路由名> \| <路径> \| <规范化查询串> \| <鉴权指纹>`（指纹 ＝ `sha256(key)` 前 16 位，**只驻内存**）；**只缓存 200**；**错误面 401/404/405/500/503 一律不得缓存**；**条目上限 128（FIFO）** | 去鉴权指纹；错误面入缓存；TTL > 60s 未升版；改为无界 |
| 边缘（第 2 级） | **仅 200** 用 **`Vercel-CDN-Cache-Control`**（现状 `public, s-maxage=60, stale-while-revalidate=300`）；**客户端 `Cache-Control` 仍 `no-store`**；**`Vercel-CDN-Cache-Control` 不回传客户端**；**`Vary: Authorization, X-API-Key` 为新增头** | 该头回传客户端；客户端 `Cache-Control` 改可缓存；无 / 错 `Vary`；用 `Cache-Control` 本体承载边缘指令 |

- **线上实测（本单，带 `X-API-Key` 的 200）**：`cache-control: no-store` ／ `vary: Authorization, X-API-Key` ／ `x-vercel-cache: HIT` ／ **无 `vercel-cdn-cache-control`** ⇒ **与上表口径一致**。
- **平台约束（如实登记、不判负）**：**带 `Authorization` 头的请求被 Vercel CDN 判不可缓存（BYPASS）** ⇒ **边缘缓存只对 `X-API-Key` 形态生效**；`Authorization` 形态仍受实例级缓存保护。**不得据此判负**，**也不得据此删去 `Authorization` 支持**（AC-117 一字未改）。
- **延迟读数（实现方自测、只引）**：**p50 2.5–3.5s → ≈0.5s（命中实例缓存）/ 1.5–2.0s（强制回源）**。**该读数不是验收结论**。

## 五、并发验收判据与阶段基线（可判负、可复跑；规范落位 §7.12-5 / AC-126、AC-127）

- **判据（两条同时成立）**：**5 路并发 plain ≥ 60 发 ⇒ 非 200 = 0**；**5 路并发 unique ≥ 60 发 ⇒ 非 200 = 0**（unique ＝ 每发不同 `offset` / 查询串以**绕开实例缓存**，即强制回源面）。
- **两类的意义**：**只跑 plain 会被实例缓存掩盖回源面（plain 全绿不构成通过）**；**只跑 unique 会漏缓存键 / 分桶缺陷**。
- **判负口径**：**任一非 200（含 500 / 503 / 超时 / 连接重置）即判负**；**不做「偶发 1 发」豁免**；**不设耗时阈值**（耗时只作读数）。
- **复跑配方**：**分段 ≤ 30 发**（本机前台命令约 420s 掉输出的既有坑）→ **逐发 append TSV**（`ts` / 序号 / URL / 状态码 / 耗时ms）→ **plain 与 unique 分开跑、互不并发** → **TSV + 汇总（`total` / `non200` / `p50` / 错误码分布）落 `qa-recheck/`**（`/tmp/qc` 不作证据）。
- **阶段基线（如实登记；不是判负线）**：**改前（默认区、无缓存）5 路并发约 20% 挂**（每轮恰 1/5、`500` 耗时 16.6–18.4s）。**不得把 80% 成功当通过，也不得把 20% 挂固化为容忍值。**
- **改后读数（实现方自测、只引）**：**间隔全绿；5 路并发 × 3 轮 15/15 全 200；p50 ≈0.5s / 1.5–2.0s**。**★ 不构成验收结论** —— 验收须由质检角色按上述配方复跑留档。
